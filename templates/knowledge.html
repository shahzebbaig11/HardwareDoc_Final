Three Distinct Components

📏 Knowledge Base (Rules)

A set of IF-THEN production rules authored by a domain expert. Each rule specifies one or more premises (conditions) and a conclusion (a specific hardware fault). The knowledge base represents expert knowledge about hardware diagnosis. It is stored in data/rules.json and is separate from the dataset.

📊 Dataset (Educational Cases)

A structured set of educational diagnostic case records. Each case documents a known set of symptom facts, the expected conclusion, and the reasoning pathway. These cases are manually authored educational examples, not measured real-world data. They are used to validate the knowledge base and to illustrate expected reasoning paths. Stored in data/hardware_diagnostic_dataset.json.

🧠 Working Memory (Session State)

During a diagnosis session, the engine maintains a working memory of all facts that have been established (True, False, or Unknown) from the user's answers. Working memory is session-specific — it is created fresh for each diagnosis and does not persist in the database. Only the results and inference summary are saved.
